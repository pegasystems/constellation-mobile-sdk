# Release notes - Constellation Mobile SDK v6.0.0

## Overview

Constellation Mobile SDK v6.0.0 adds ObjectReference components and improves logging, selectable-table validation, and WebView lifecycle handling. This release also changes public configuration and UI APIs, so applications and libraries must update affected code and rebuild.

## Highlights

### ObjectReference component

Added support for the `ObjectReference` component, enabling DataReference support in Pega 26 at the same scope as Pega 25.

### Logging and WebView inspection

The new process-wide `ConstellationSdk.debuggable` setting controls SDK diagnostic logging and WebView inspection. It defaults to `false`: SDK informational, debug, and verbose messages, including forwarded custom-component console messages, are suppressed, while warnings and errors remain visible. Set it before creating the engine and SDK, and avoid changing it during a flow. Existing WebViews are not automatically reconfigured for inspection when it changes.

Host-application logs, independently emitted provider logs, and the browser inspector's original console are outside this filter. See [Debugging and inspection](../../core/README.md#debugging-and-inspection) for platform behavior.

## Breaking changes

| Module | Before (v5.0.0) | After (v6.0.0) and compatibility impact |
| --- | --- | --- |
| `core` | `ConstellationSdkConfig.debuggable` and its constructor argument configured debugging per SDK instance. | `ConstellationSdk.debuggable` is shared by all instances. Removing the configuration property changes the constructor and data-class methods: **source and binary incompatible**. |
| `engine-webview` | Engine reuse after `destroy()` was not consistently rejected. | Destruction is terminal. `configure()` and `performAction()` on a destroyed Android or iOS WebView engine throw `IllegalStateException`. This is a **behavioral change**, with no source or binary signature change. |
| `core`<br>`engine-webview` | `AlertBannerComponent.messages` contained `List<String>`, and banner bridge payloads contained an array of strings. | Messages are `List<AlertBannerComponent.Message>` with `message` and `isFieldMessage`; bridge payloads contain corresponding objects. **Source incompatible**, and existing binaries that treat elements as strings can fail at runtime even though the JVM getter still returns an erased `List`. Custom bridge producers and consumers must also update the payload shape. |
| `ui-components-cmp` | Compose `Table` accepted selection and data arguments without validation or state flags. | `Table` requires `validateMessage`, `required`, and `disabled` arguments. Its signature is **source and binary incompatible**. |
| `ui-components-cmp` | Compose `Label` had no `fontWeight` parameter. | `Label` accepts an optional `fontWeight`. Ordinary source calls remain compatible, but the compiled signature is **binary incompatible**; typed callable references may also need updating. |

### Migration

The changes above compare the v5.0.0 codebase with v6.0.0. If upgrading from v4.x, also follow the [v5.0.0 migration guidance](v5.0.0.md#migration).

1. Update SDK dependencies to `6.0.0` and rebuild applications and any libraries or frameworks compiled against the previous SDK. Move the debug setting out of `ConstellationSdkConfig` and set it before engine initialization:

   ```kotlin
   // Before
   val config = ConstellationSdkConfig(pegaUrl = pegaUrl, debuggable = debugEnabled)

   // After
   ConstellationSdk.debuggable = debugEnabled
   val config = ConstellationSdkConfig(pegaUrl = pegaUrl)
   ```

   In Swift, make the equivalent change:

   ```swift
   // Before
   let config = ConstellationSdkConfig(
       pegaUrl: pegaUrl, componentManager: componentManager, debuggable: debugEnabled
   )

   // After
   ConstellationSdkCompanion().debuggable = debugEnabled
   let config = ConstellationSdkConfig(pegaUrl: pegaUrl, componentManager: componentManager)
   ```

   Choose `debugEnabled` from the host application's build configuration and enable it only where diagnostic output and inspection are appropriate. The setting is global and is not inferred automatically from the build type.

2. After destroying an engine, create a new engine and SDK rather than reconfiguring or performing an action on the old instance:

   ```kotlin
   engine.destroy()
   val nextEngine = AndroidWebViewEngine(context, scope, callFactory)
   val nextSdk = ConstellationSdk.create(config, nextEngine)
   ```

   The same lifecycle rule applies to `WKWebViewBasedEngine`. See the [engine lifecycle guide](../../engine-webview/README.md#engine-lifecycle).

3. Update custom alert-banner renderers to read each message's text and, if needed, its classification:

   ```kotlin
   // Before
   val texts: List<String> = banner.messages

   // After
   val texts: List<String> = banner.messages.map { it.message }
   val fieldMessages = banner.messages.filter { it.isFieldMessage }
   ```

   SwiftUI renderers can enumerate the typed messages and display `message.message`:

   ```swift
   // After
   ForEach(Array(component.messages.enumerated()), id: \.offset) { _, message in
       Text(message.message)
   }
   ```

   Custom bridge code that produces banner props must change `messages: ["Error"]` to `messages: [{ message: "Error", isFieldMessage: true }]` for a field error; use `false` for page and HTTP messages.

4. Supply the new arguments when calling `Table` directly:

   ```kotlin
   // Before
   Table(
       label = label,
       selectionMode = selectionMode,
       columns = columns,
       columnsLabels = columnsLabels,
       items = items,
       selectedItem = selectedItems,
       onItemClick = onItemClick
   )

   // After: use these defaults to preserve the previous behavior
   Table(
       label = label,
       validateMessage = "",
       selectionMode = selectionMode,
       columns = columns,
       columnsLabels = columnsLabels,
       items = items,
       selectedItem = selectedItems,
       required = false,
       disabled = false,
       onItemClick = onItemClick
   )
   ```

   When rendering a `ListViewComponent`, pass its `validateMessage`, `required`, and `disabled` properties instead of the defaults to reflect the configured field state.

5. Recompile direct `Label` callers. Calls such as `Label(label = label)` need no source change; adapt any callable reference that expects the old parameter list. `fontWeight` is optional.

## Bug fixes

- **Selectable tables**: Required indicators and validation messages are passed to ListView tables. Disabled rows, radio buttons, and checkboxes cannot change selection. Validation-only updates no longer trigger a table data reload, and existing property errors are not cleared while a validation message remains.
- **Alert banners**: Field-validation messages are classified separately from page and HTTP messages while their text remains visible in the built-in renderers.
- **Reference selection**: Card clicks are no longer forwarded to their child components, and multiselect insertion no longer sends a duplicate update. ObjectReference handling also accounts for nested display paths, composite keys, and display-only multiple selections.
- **Engine teardown**: Pending Android event delivery and late Android and iOS WebView callbacks are prevented from continuing initialization or updating a destroyed engine.
- **Case-summary refresh**: Embedded forms disable deferred case-summary updates when the CoreJS feature-map method is available. If it is unavailable, the engine logs a warning and keeps the existing runtime behavior.
- **Sample layouts**: The CMP sample respects navigation-bar insets, the SwiftUI sample's static tab bar uses an iOS 26-compatible layout, and the iOS sample app icon retains a white background in dark mode.
