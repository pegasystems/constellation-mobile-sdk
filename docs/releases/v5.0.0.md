# Release notes - Constellation Mobile SDK v5.0.0

## Overview

Constellation Mobile SDK v5.0.0 gives custom renderers access to alternate design-system configuration and lets the Android WebView engine accept any OkHttp `Call.Factory`. It also hardens the JavaScript bridge and fixes DataReference read-only and visibility issues. Data-page option loading now handles errors more reliably. Building the SDK on Windows now works too.

## Highlights

### Alternate design-system configuration

Every component now inherits `configAlternateDesignSystem` from `BaseComponent`. It holds the server-resolved `configAlternateDesignSystem` value as a `JsonObject`, so built-in and custom renderers can read design-system-specific settings. The SDK doesn't need a dedicated property for each setting. The value refreshes on every component update. It's `null` when the server doesn't provide the configuration.

For details and an example, see [Alternate design-system configuration](../../core/README.md#alternate-design-system-configuration).

### Android WebView engine accepts `Call.Factory`

`AndroidWebViewEngine` now accepts any `okhttp3.Call.Factory` implementation for DX and non-DX network requests, not only `OkHttpClient`. Integrations can now wrap or decorate the network client, for example to add instrumentation or custom call handling. `OkHttpClient` still works because it implements `Call.Factory`.

## Breaking changes

The `AndroidWebViewEngine` public API changed:

| Before (v4.x) | After (v5.0.0) |
|--------|-------|
| Constructor parameter `okHttpClient: OkHttpClient` | `callFactory: Call.Factory` |
| Constructor parameter `nonDxOkHttpClient: OkHttpClient` | `nonDxCallFactory: Call.Factory` |
| `AndroidWebViewEngine.defaultHttpClient()` | `AndroidWebViewEngine.defaultCallFactory()` |

The constructor's JVM signature changed, so this release is binary-incompatible with v4.x. You must recompile any code built against v4.x, including other libraries that create `AndroidWebViewEngine`.

### Migration

1. Update the SDK dependency to `5.0.0` and recompile.
2. If you pass the network clients as named arguments, rename them:

    ```kotlin
    // v4.x
    AndroidWebViewEngine(context, scope, okHttpClient = client, nonDxOkHttpClient = nonDxClient)

    // v5.0.0
    AndroidWebViewEngine(context, scope, callFactory = client, nonDxCallFactory = nonDxClient)
    ```

3. Replace calls to `AndroidWebViewEngine.defaultHttpClient()` with `AndroidWebViewEngine.defaultCallFactory()`.

If you pass an `OkHttpClient` positionally, your source code works as it is. `OkHttpClient` implements `Call.Factory`, so recompiling is enough.

## Bug fixes

- **DataReference read-only mode**: DataReference fields now pass read-only and display-only mode on to their child components, including selectable cards.
- **Hidden required fields**: The SDK now removes hidden components and their descendants from the CoreJS context tree. Required fields inside invisible views or DataReferences no longer block form submission.
- **Data-page option load errors**: When loading options for DataReference and data-page-backed select fields (for example, cascading dropdowns) fails, the field now shows an empty option list and logs a warning. Previously, the failure went unhandled. The SDK also ignores responses from older requests that arrive late, so they can't overwrite newer options.
- **JavaScript bridge sanitization**: On Android and iOS, the SDK now encodes component IDs and event payloads as proper JavaScript string literals before sending them to the WebView. Values that contain quotes, backslashes, line breaks, or Unicode line separators (`U+2028`, `U+2029`) no longer break event delivery.
- **WebView resource packaging on Windows**: The SDK now keeps its bundled JavaScript resources directly in `engine-webview/src/commonMain/composeResources/files/scripts/` instead of linking to them through a symbolic link. Builds on Windows now package them correctly. For details, see the [WebView engine README](../../engine-webview/README.md).
- **Component update flow**: Improved WebView component updates and context re-subscription. Shared update logic now lives in `BaseComponent`. Prop and parameter comparisons now use deep equality instead of comparing JSON strings.
- **Selectable cards**: Added spacing around selectable cards.

## Documentation

- Documented the minimum Android System WebView version (Chromium 103 or later). The Android integration guide now also explains how to update and verify the WebView provider.
- Updated the Android and Compose Multiplatform integration guides for the `Call.Factory` engine parameters.
- Added the [Setting up new Pega application with SDK](../setup-sample-pega-app.md#setting-up-new-pega-application-with-sdk) guide. It explains how to register an OAuth 2.0 client so the sample apps can connect to any Pega application.
- Documented `BaseComponent` metadata (`pConnectPropertyReference`, `parentId`, and `configAlternateDesignSystem`) in the [core README](../../core/README.md#component-metadata).

## Testing and tooling

- Added Pega 26.1.1 mock fixtures and tests for cascading dropdowns, hidden required fields, and read-only and display-only DataReference cards.
- Added unit tests for JavaScript string-literal encoding and WebView resource packaging.
- Updated Android UI tests to work with the latest emulator image (added Espresso `3.7.0` as a test dependency).
- CI now runs tests for pull requests from forks.

For supported components and integration instructions, see the [project README](../../README.md).
